# ٧ — النسخة الاحتياطية اليومية بالبريد

الخطة المجانية في Supabase **لا تتضمّن نسخًا احتياطيًا تلقائيًا** — النسخ اليومي
يبدأ من الخطة المدفوعة. هذا الملف يشرح بديلًا مجانيًا: مهمة يومية على
GitHub Actions تسحب كل الجداول وترسلها مضغوطة إلى بريدك.

كل الخطوات تتم من متصفح الموبايل — لا تحتاج كمبيوتر.

## ما الذي يُنسَخ؟

البيانات فقط (كل جدول كملف CSV). أما بنية قاعدة البيانات — الجداول والدوال
والصلاحيات — فهي محفوظة أصلًا في مجلد `sql/`.

> **الاستعادة = ملفات `sql/` بالترتيب + استيراد ملفات CSV.**

## قبل أن تبدأ: اجعل المستودع private

المهمة ستحتاج مفتاح `service_role`، والأنظف ألّا يكون المستودع عامًا.
GitHub Pages لا تعمل على المستودعات الخاصة إلا باشتراك، لذا انقل الاستضافة
إلى Cloudflare Pages أولًا — وهي تنشر من المستودعات الخاصة مجانًا.

> ملاحظة: المفاتيح في GitHub Secrets مشفّرة ولا تظهر في السجلات حتى في
> المستودع العام. جعل المستودع خاصًا طبقة احتياط إضافية، لا شرطًا تقنيًا.

## ١) كلمة مرور تطبيق من جيميل

جيميل لا يقبل كلمة مرور حسابك من برنامج خارجي — يحتاج كلمة مرور تطبيق:

1. افتح **myaccount.google.com** ← الأمان
2. فعّل **التحقّق بخطوتين** إن لم يكن مفعّلًا (شرط إجباري)
3. ارجع للأمان ← ابحث عن **كلمات مرور التطبيقات**
4. أنشئ واحدة باسم `mp-store-backup`
5. انسخ الـ ١٦ حرفًا الظاهرة — **لن تظهر مرة أخرى**

## ٢) أضف الأسرار الخمسة

في المستودع: **Settings** ← **Secrets and variables** ← **Actions**
← **New repository secret**. أضف واحدًا واحدًا:

| الاسم | القيمة |
|---|---|
| `SUPABASE_URL` | رابط المشروع من Supabase ← Settings ← API |
| `SUPABASE_SERVICE_KEY` | مفتاح `service_role` من نفس الصفحة |
| `MAIL_USERNAME` | بريد جيميل الذي سيُرسل منه |
| `MAIL_PASSWORD` | كلمة مرور التطبيق من الخطوة السابقة |
| `MAIL_TO` | البريد الذي يستقبل النسخة (يمكن أن يكون نفسه) |

> ⚠️ مفتاح `service_role` يتجاوز كل سياسات RLS. مكانه هنا فقط —
> لا في `config.js` ولا في أي ملف داخل المستودع.

## ٣) ارفع الملفين

| الملف | المسار |
|---|---|
| `backup.py` | `tools/backup.py` |
| `daily-backup.yml` | `.github/workflows/daily-backup.yml` |

لإنشاء المسار الثاني من الموبايل: **Add file** ← **Create new file**،
واكتب في خانة الاسم `.github/workflows/daily-backup.yml` كاملًا —
GitHub ينشئ المجلدات تلقائيًا عند كتابة `/`.

## ٤) جرّبها الآن

تبويب **Actions** ← **نسخة احتياطية يومية** ← **Run workflow**.
خلال دقيقتين تصلك رسالة بمرفق `mp-store-backup-YYYY-MM-DD.zip`.

بعد نجاحها تعمل وحدها كل يوم الساعة ٢-٣ فجرًا بتوقيت القاهرة.

## فائدة جانبية

مشروع Supabase المجاني يدخل في سبات بعد **٧ أيام** بلا أي نداء.
المهمة تناديه يوميًا، فلن يحدث ذلك حتى في إجازة طويلة.

## التكلفة

صفر. المستودعات الخاصة لها ٢٠٠٠ دقيقة شهريًا مجانًا، والمهمة تستهلك
أقل من دقيقة يوميًا.

## الاستعادة عند الحاجة

1. أنشئ مشروع Supabase جديدًا
2. شغّل `sql/01` حتى `sql/06` بالترتيب
3. Table Editor ← Import data from CSV، واستورد الملفات
   **بنفس ترتيب الجداول المذكور في نص الرسالة** — الأب قبل الابن،
   وإلا رفضت المفاتيح الأجنبية الاستيراد
4. شغّل `select public.recalc_balances();`
   ثم `select public.recalc_avg_cost();`
5. عدّل `SUPABASE_URL` و`SUPABASE_ANON_KEY` في `src/config.js`

## استكشاف الأخطاء

| العرض | السبب | الحل |
|---|---|---|
| `HTTP 401` | المفتاح خطأ أو هو مفتاح anon | استخدم `service_role` |
| `HTTP 404` على جدول | الجدول غير موجود | احذف اسمه من `TABLES` في `backup.py` |
| فشل الإرسال `535` | كلمة مرور التطبيق خطأ | أنشئ واحدة جديدة |
| لم تعمل المهمة تلقائيًا | المستودع خامل | GitHub يوقف الجدولة بعد ٦٠ يومًا بلا نشاط — شغّلها يدويًا مرة |
| المرفق كبير جدًا | تجاوز ٢٥ ميجابايت (حد جيميل) | نرفعه على مكان آخر ونرسل رابطه — تعديل بسيط |
