# ١ — إنشاء قاعدة البيانات على Supabase

الوقت المتوقع: ١٥ دقيقة. لا تحتاج بطاقة ائتمان.

## الخطوة ١: إنشاء المشروع

1. افتح <https://supabase.com> واضغط **Start your project** وسجّل بحساب GitHub أو بريد إلكتروني.
2. **New project**، واملأ:
   - **Name**: `mp-store`
   - **Database Password**: كلمة مرور قوية — **احفظها في مكان آمن**، لن تظهر مرة أخرى.
   - **Region**: `Central EU (Frankfurt)` — الأقرب لمصر من حيث زمن الاستجابة.
3. اضغط **Create new project** وانتظر دقيقتين حتى يكتمل التجهيز.

## الخطوة ٢: تشغيل ملفات قاعدة البيانات

من القائمة الجانبية افتح **SQL Editor** ثم **New query**، وشغّل الملفات
**بهذا الترتيب بالضبط** (انسخ محتوى كل ملف والصقه ثم اضغط **Run**):

| # | الملف | ما يفعله |
|---|---|---|
| 1 | `sql/01_schema.sql` | إنشاء الجداول والفهارس |
| 2 | `sql/02_functions.sql` | الدوال والمُشغِّلات: تحديث الأرصدة، ترقيم الأذون، إنشاء الأذون، التقارير |
| 3 | `sql/03_security.sql` | سياسات الصلاحيات وتفعيل التحديث اللحظي |
| 4 | `sql/04_seed.sql` | الإعدادات الأولية والفئات |

لو ظهر خطأ في ملف، أوقف التنفيذ وأصلحه قبل الانتقال للتالي — الملفات مترتبة على بعضها.

## الخطوة ٣: ضبط طريقة الدخول

المستخدمون يدخلون **باسم مستخدم** لا ببريد إلكتروني. النظام يحوّل الاسم داخليًا
إلى `اسم_المستخدم@mp-store.local`. لذلك:

1. افتح **Authentication → Providers → Email**.
2. أطفئ **Confirm email** (لأن النطاق وهمي ولن يصل بريد تأكيد).
3. احفظ.

> إن أردت استخدام بريد الشركة الحقيقي بدلًا من ذلك، اتركه مفعّلًا،
> وغيّر `LOGIN_DOMAIN` في `src/config.js` إلى نطاق شركتك.

## الخطوة ٤: إنشاء حساب المدير

1. **Authentication → Users → Add user → Create new user**.
2. Email: `admin@mp-store.local` — Password: كلمة مرور قوية.
3. فعّل **Auto Confirm User**.
4. ارجع إلى **SQL Editor** وشغّل:

```sql
update public.profiles
   set role = 'admin', full_name = 'مدير المخزن', username = 'admin'
 where id = (select id from auth.users where email = 'admin@mp-store.local');
```

هذا الحساب هو الوحيد الذي يستطيع إنشاء بقية المستخدمين من داخل النظام لاحقًا.

## الخطوة ٥: نسخ بيانات الاتصال

**Project Settings → API**، وانسخ:

- **Project URL** → مثل `https://abcdefgh.supabase.co`
- **anon public** key → نص طويل يبدأ بـ `eyJ...`

ضعهما في `src/config.js`:

```js
export const SUPABASE_URL = "https://abcdefgh.supabase.co";
export const SUPABASE_ANON_KEY = "eyJhbGciOi...";
```

> **مفتاح `anon` علني بطبيعته** ولا ضرر من وجوده في الكود — الحماية الحقيقية
> من سياسات RLS التي شغّلتها في الخطوة ٢.
> **لا تضع مفتاح `service_role` هنا إطلاقًا**؛ هذا المفتاح يتجاوز كل الصلاحيات.

## الخطوة ٦: نسخة احتياطية مجدولة

Supabase يأخذ نسخة يومية تلقائيًا في الخطة المجانية.
للاحتفاظ بنسخة عندك أيضًا: من داخل النظام → **الإعدادات → تنزيل نسخة كاملة (Excel)**
مرة أسبوعيًا، واحفظها على درايف الشركة.

## حلول لمشاكل شائعة

| العرض | السبب | الحل |
|---|---|---|
| `Invalid login credentials` | كلمة مرور خطأ أو المستخدم غير موجود | أعد ضبط كلمة المرور من Authentication → Users |
| `لا يوجد ملف مستخدم مرتبط` | صف `profiles` لم يُنشأ | تأكد أن `02_functions.sql` شُغِّل، ثم أنشئ الصف يدويًا |
| `new row violates row-level security` | الدور لا يملك الصلاحية | راجع دور المستخدم في جدول `profiles` |
| الصفحة تقول "تعذّر الوصول إلى الخادم" | المشروع في سبات | افتح لوحة Supabase واضغط **Restore project** |
